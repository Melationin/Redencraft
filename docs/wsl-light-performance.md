# WSL 世吞光照性能分析

在 Ubuntu 24.04 / WSL 2（6.6.87.2-microsoft-standard-WSL2）上，用 GCC 13.3、Release（`-O3 -DNDEBUG -g`）和同一份 Linux jemalloc 5.3.0 跑五组交错测试，每组各 1000 刻。模拟线程绑 WSL CPU 2，光照线程绑 CPU 4；Linux 拓扑报告两者为不同核心。这个结果是 WSL 内部对照，不能与此前的 Windows/MSVC 数字直接相减。

前光照基线 `00c15ea` 在仓库外解包，应用同样的队列初始化位置修复及 Linux 线程 CPU 计时；模拟逻辑和计时循环不改。候选为 `9a566dc` 加本次可移植性改动。世吞投影 SHA-256：`7ad76ac215039e66594a81feb45dae70896827c768328133d19b86d3e8d91e52`。正式轮无诊断指纹和采样开销；每轮先完成初照，计时中不等 worker。基线/关光/双光四个模拟检查点及终态一致；有光独立诊断的四个双层光照指纹都发生变化。

| 方案 | 模拟线程 CPU / 1000 刻（ms） | 平均刻墙钟（ms） | P95（ms） |
|---|---:|---:|---:|
| 前光照基线 | 2816.302 | 2.791 | 6.009 |
| 当前关光 | 2761.876 | 2.762 | 6.011 |
| 当前双光 | 3038.923 | 3.124 | 6.587 |

表中是各方案原值中位数。按每组计算增幅再取中位数，双光相对前光照基线为 **CPU +7.90%、平均刻墙钟 +13.27%、P95 +11.08%**；相对当前关光为 **+13.01%、+16.13%、+12.95%**。正式门槛要求相对前光照基线 CPU 和平均刻均低于 10%，本轮平均刻未达标；双光正式轮均无 >50 ms 的刻。

每轮初照 16.76–17.89 s。正式计时内，模拟线程接收了 5,120–5,861 个天空光区段变化、260–313 个方块光区段变化，无拒绝。末尾报告有 152 个 pending/busy 区块，计时之外等待 worker 完成需 0.67–1.06 s，随后排空。这里的 pending/busy 区块数不含 ring 当前占用；`light_queue` 是累计传播条目，不能拿来表示积压。

另外用 `perf` 的用户态 CPU 时钟（397 Hz、DWARF 调用栈）在初照后的正式 1000 刻窗口附近分别采关光、双光一轮。这两轮不参与上表计时：

- 双光 worker 共 1,474 个样本，**91.5%** 的调用栈经过天空光传播器，方块光为 **3.5%**；合并环记录为 **3.8%**。这些是调用栈覆盖率，不是可相加的互斥阶段时间。
- worker 的天空光 `storedLevel` 覆盖 **54.5%** 的样本；单个区段工作层哈希查询函数本身占 **21.6%** 的叶样本。源码入口见 `src/light.cpp` 的 `SkyLightPropagator::storedLevel`：单区段缓存命中可直接读，但跨区段时仍查工作层哈希表，遇到缺层还向上找可继承的底平面。
- 模拟线程的双光样本中 `World::setBlock` 调用栈占 **39.0%**（关光 **34.4%**），直接的 `reportBlockCell` 路径只命中 **9 / 1447** 个样本。前者还包含方块和邻居更新，不能全归因给光照；采样也不统计等待锁的墙钟时间。

下一轮先在后台减少同一区段的重复寻址，以及缺层向上查询：考虑为参与传播的区块维护按区段号直接索引的工作层/上方有效层视图。必须保留缺层、底面继承、跨空段补撤光和不可变发布语义；再用双光端到端对照验证墙钟和积压是否下降。主线程可另做分段计时，拆开光学比较、提交与接收；现有样本不支持先重写入队。

验证：Linux 全量构建成功。第一轮 CTest 的 28 项通过；唯一失败为生成 C++ 光学表与迁入文件的 CRLF 字节差异。校验改为比较文本后只重跑该项，通过；原版导出资产仍核对精确哈希。未重新运行真实 26.1 服务端。
