# Anvil loading

Saved tick import now follows vanilla's per-chunk `LevelChunkTicks.unpack`: signed subTickOrder values `-N..-1` in saved-list order, with duplicate pending entries retained in the queue. Live new ticks use nonnegative sequence values. This was verified by the [SafeSave-inspired ordering probes](../validation/safesave_order/README.md).

The reader opens `level.dat` from the world directory and `r.x.z.mca` files from a caller-selected dimension's `region` directory. It reads `Data.Time` as the current game time. The caller supplies the dimension's vertical bounds; the default is the standard overworld range [-64, 320). Custom dimension metadata is not resolved automatically. Only chunks present on disk are loaded; absent chunks are not generated. The reader checks chunk positions, region allocation and lengths, and preserves unknown block names and string properties rather than mapping them to air. The modern `sections` / `block_states` layout is supported; older chunk formats and data fixing are not implemented. World and chunk DataVersion must equal 4786 (26.1), and chunk status must be full; other versions and incomplete chunks are rejected because data fixing and generation are not implemented.

Section palette values use the modern non-spanning long layout with a minimum of four bits per block. Palette indices and exact packed-array lengths are checked. Single-entry palettes are expected to omit the packed data. Gzip, zlib, uncompressed, and vanilla legacy LZ4Block region records and external `.mcc` chunks are supported; LZ4 blocks are checked using their XXH32 checksums. `level.dat` must be gzip compressed.

Saved block ticks retain their relative delay and priority and are scheduled against the loaded game time. Fluid ticks and raw block entity tags remain in `LoadedWorld` but are not simulated by the importer. Moving piston entities are imported, including state, direction, progress, and source/extending flags. Other block entity types require implementation. The caller should report these limitations to users. The importer does not read entities, block events, or global game rules, and does not write world data.

NBT is implemented locally to avoid a separate vendored dependency and to retain all tag types for unsupported block entities. The parser checks lengths, input bounds, nesting depth, node count, decompressed size, tag types, and duplicate keys. Invalid files raise `nbt::Error`; zlib supplies decompression. The parser limits decompressed NBT to 128 MiB and region files to 512 MiB. These limits intentionally reject unusually large inputs.

The storage fixture checks negative chunk coordinates, unknown names/properties, a five-bit palette across a long boundary, truncated NBT, and a malformed region record. These are C++ regression checks, not a differential test against a running 26.1 server.

The legacy block framing follows [lz4-java LZ4BlockInputStream](https://github.com/lz4/lz4-java/blob/master/src/java/net/jpountz/lz4/LZ4BlockInputStream.java), including the 28-bit checksum exposed by [StreamingXXHash32.asChecksum](https://github.com/lz4/lz4-java/blob/master/src/java/net/jpountz/xxhash/StreamingXXHash32.java). LZ4 and XXH32 C implementations are vendored from lz4 v1.10.0 under its BSD 2-Clause license.
