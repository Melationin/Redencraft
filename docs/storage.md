# Anvil loading

Saved tick import now follows vanilla's per-chunk `LevelChunkTicks.unpack`: signed subTickOrder values `-N..-1` in saved-list order, with duplicate pending entries retained in the queue. Live new ticks use nonnegative sequence values. This was verified by the [SafeSave-inspired ordering probes](../validation/safesave_order/README.md).

The reader opens `level.dat` from the world directory and `r.x.z.mca` files from a caller-selected dimension's `region` directory. `dimensionRegionDirectory` / `defaultRegionDirectory` resolves 26.1's `dimensions/<namespace>/<path>/region` (preferring `<world>/region` for `minecraft:overworld`, `DIM-1/region` for `minecraft:the_nether`, and `DIM1/region` for `minecraft:the_end` when modern folders are absent only if those legacy directories exist, and preferring modern `dimensions/minecraft/...` first). It reads `Data.Time` as the current game time, and `world_gen_settings.dat` (`data.dimensions`) parses builtin or inline `DimensionTypeSpec` entries with vertical bounds, environment attributes (`water_evaporates`, `fast_lava`), sky-light flags, and `default_clock`. Only chunks present on disk are loaded; absent chunks or absent dimensions are not generated. The reader checks chunk positions, region allocation and lengths, and preserves unknown block names and string properties rather than mapping them to air. The modern `sections` / `block_states` layout is supported; older chunk formats and data fixing are not implemented. World and chunk DataVersion must equal 4786 (26.1), and chunk status must be full; other versions and incomplete chunks are rejected because data fixing and generation are not implemented.

Section palette values use the modern non-spanning long layout with a minimum of four bits per block. Palette indices and exact packed-array lengths are checked. Single-entry palettes are expected to omit the packed data. Gzip, zlib, uncompressed, and vanilla legacy LZ4Block region records and external `.mcc` chunks are supported; LZ4 blocks are checked using their XXH32 checksums. `level.dat` must be gzip compressed.

Saved block ticks retain their relative delay and priority and are scheduled against the loaded game time. Fluid ticks are restored the same way, into the world's **separate** fluid `LevelTicks` container, with their exact fluid identity preserved: `fluid_ticks` entries carry `minecraft:water` / `minecraft:flowing_water` / `minecraft:lava` / `minecraft:flowing_lava` / `minecraft:empty`, and dispatch matches on exact identity, so a source entry never fires for a flowing cell. Because `LevelChunk.java:639-641` unpacks `blockTicks` and `fluidTicks` as two containers, each saved list gets its **own** `-N..-1` subTick base per chunk instead of sharing one counter. An explicit `minecraft:empty` entry is a real identity and is restored; an unknown or empty fluid name is rejected as a data error rather than silently dropped. Raw block entity tags remain in `LoadedWorld` but are not simulated by the importer; moving piston entities are imported, including state, direction, progress, and source/extending flags. Other block entity types require implementation.

Entities are read from the selected dimension's sibling `entities/r.x.z.mca` directory. These records use `DataVersion:4786`, `Position` as a two-int chunk-coordinate array, and a compound list named `Entities`. Only records whose terrain chunk was loaded are decoded; entity storage cannot create additional chunks. Terrain and entity regions share allocation, length, compression, checksum and external `.mcc` handling. Terrain's legacy lowercase `entities` list is also read (`SerializableChunkData`); the former uppercase spelling is accepted only when lowercase is absent. Raw `LoadedWorld.entities` retains all selected records for inspection. During import, duplicate supported entities with the same four-int UUID are skipped after the first successful import, with legacy terrain records preceding modern records. UUID-less records remain separate; UUID identity is not yet retained on live simulated entities.

`minecraft:item`, `minecraft:tnt`, `minecraft:falling_block`, and `minecraft:minecart` are imported with position, motion, rotation and the vanilla type fields described in [entities.md](entities.md). Unknown entity types remain raw without requiring or interpreting `Pos`/`Motion`. Supported entities are imported only when their clamped position belongs to a loaded terrain chunk. Position bounds follow `Entity.load` (X/Z ±30,000,512; Y ±20,000,000), and motion components exceeding an absolute value of ten are individually replaced with zero. NaN positions/motion and invalid rotations are rejected before C++ integer conversion; rejection of NaN motion is stricter than Java's floating-point path. Missing motion/rotation default to zero. Minecart `HasTicked` is copied directly to `firstTick`, preserving the counterintuitive vanilla read/write behavior. Passengers, owners, custom names and item components remain TODOs.

The world seed comes from 26.1's gzip `data/minecraft/world_gen_settings.dat`, root `DataVersion:4786`, then `data.seed`, matching `LevelStorageSource.readExistingSavedData` and `WorldGenSettings.TYPE`. An old embedded `level.dat/Data.WorldGenSettings.seed` is a compatibility fallback only if the modern file is absent; obsolete `RandomSeed` is ignored. If neither source exists the simulator deterministically uses zero; vanilla instead falls back to random world options. Present malformed seed files are rejected. The Java-compatible random source is initialized from this seed, but its sequence is not promised to match a real server. The importer does not read block events or global game rules, and does not write world data.

NBT is implemented locally to avoid a separate vendored dependency and to retain all tag types for unsupported block entities. The parser checks lengths, input bounds, nesting depth, node count, decompressed size, tag types, and duplicate keys. Invalid files raise `nbt::Error`; zlib supplies decompression. The parser limits decompressed NBT to 128 MiB and region files to 512 MiB. These limits intentionally reject unusually large inputs.

Storage fixtures check negative chunk coordinates, unknown names/properties, a five-bit palette across a long boundary, truncated NBT, malformed region records, modern dimension-path precedence, selected-dimension entity regions, all four compression formats with inline/external payloads, UUID duplicate handling, unknown entities without positions, version/coordinate mismatches, seed-source precedence, minecart flags and numeric import safety. These are C++ regression checks, not a differential test against a running 26.1 server.

On 2026-11-06, a read-only smoke check also used the existing vanilla `carpet-validation-world` save: its original terrain and entity records for chunk `(0,0)`, `level.dat` and `world_gen_settings.dat` were copied into the ignored build directory, retaining their original compressed payloads. The CLI loaded one terrain chunk, 43,594 non-air blocks and four supported simple entities; two other raw entity records remained unimplemented. No server/client was launched. This checks real 26.1 file compatibility, not simulation parity for the many unsupported blocks in that save.

The legacy block framing follows [lz4-java LZ4BlockInputStream](https://github.com/lz4/lz4-java/blob/master/src/java/net/jpountz/lz4/LZ4BlockInputStream.java), including the 28-bit checksum exposed by [StreamingXXHash32.asChecksum](https://github.com/lz4/lz4-java/blob/master/src/java/net/jpountz/xxhash/StreamingXXHash32.java). LZ4 and XXH32 C implementations are vendored from lz4 v1.10.0 under its BSD 2-Clause license.
