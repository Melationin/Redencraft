# Original 26.1 execution-order probes

`VanillaOrderProbe.java` runs Mojang's actual `LevelTicks<Block>` and `LevelChunkTicks<Block>` from the original 26.1 server jar (SHA-1 `3872a7f07a1a595e651aef8b058dfc2bb3772f46`) with the same fixture inputs as `cpp_cases.json`. `run.ps1` compiles and runs the probe against the previously unpacked server and bundled libraries in `../../vanilla26_1`; `vanilla-order.json` is its actual output. This is a runtime scheduler comparison, not execution of SafeSave2 or a full game server. It covers the SafeSave-inspired three-boundary scheduled block fixture, duplicate scheduled ticks, competing overdue chunk heads, and negative restored sub-tick order. Fluids, events, entities, persistence and restoration are not covered by that JSON.

Original runtime and C++ agree on fixture, duplicate, and overdue cases. For negative order, vanilla executes x=-1 (order -2) before x=16 (order 0); the recorded C++ baseline reverses them due to unsigned storage.

`OrderAgent.java` is a Java 26 `java.lang.classfile` instrumentation agent that records the head of the original server's `ServerLevel.doBlockEvent` and `PistonMovingBlockEntity.tick`; it does not alter the target method's body beyond a trace call. `run_server_trace.py` uses the original server and the agent on localhost port 25598. The `server-trace.log` records a separate piston fixture: event positions x=-2,14,8190; the moving entities that ticked were x=0,-1,16,15 in that order on each of three ticks. The x=8192 fixture did not yield a moving-entity tick in that short server run, so this is not a complete comparison against the six-position C++ moving-entity fixture. The piston event fixture is likewise not the SafeSave-inspired note-block event case. Do not treat unobserved cases as passing.

To rerun the instrumented server, compile `OrderAgent.java` with Java 26, create `order-agent.jar` with `MANIFEST.MF` and all three `OrderAgent*.class` files, review https://aka.ms/MinecraftEULA and place `eula=true` in this directory's `eula.txt` only if you accept it, then run `python run_server_trace.py`. Both server and scheduler scripts use vanilla artifacts already unpacked by the earlier `vanilla26_1` comparison.

## Matching ServerLevel fixture

`run_exact.ps1` builds the instrumentation agent and starts a separate original 26.1 server. Review and accept Mojang's EULA in this directory's `eula.txt` before running. The agent waits for every participating chunk to reach `BLOCK_TICKING` and report `areEntitiesLoaded`; then it installs the same 12 note-block event positions and duplicate requests and the same six moving piston entities as the C++ probe. It records actual `ServerLevel.doBlockEvent` and `PistonMovingBlockEntity.tick` calls, alongside snapshots after each of three ticks. Server timestamps are reported relative to the fixture setup time.

`vanilla-server-order.json` and `exact-server-trace.log` are the recorded original-server output. The fixture events, three moving-entity snapshots, and six completion calls match `cpp_cases.json`. PistonMovingBlockEntity was loaded before the instrumentation agent could register its transformer, so the agent explicitly retransforms that class; the log records `EXACT_RETRANSFORM` and `EXACT_TRANSFORM` before the fixture. These trace calls do not replace the vanilla methods. The full SafeSave2 mod/restart test and fluid/entity simulation remain outside this probe.
